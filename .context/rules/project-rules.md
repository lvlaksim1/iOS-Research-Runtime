# Project rules

1. `main` is product authority. `manager-state` is durable Project Manager authority. Neither branch silently substitutes for the other.
2. The retired `ai-agent-lab` shift-worker/OTK factory is not an execution authority for this project and must not be re-enabled for ordinary development.
3. A new chat/model/runtime is a new execution carrier of `ios-research-runtime-project-manager`, not a new shift worker.
4. Direct Owner ↔ Project Manager work is first-class. Supervisor is not a mandatory intermediary for ordinary project development.
5. The immediate milestone remains Windows provisioning and Darwin recovery boot through `launchd` to a verified root shell.
6. APFS semantic changes require discriminating evidence tied to an immutable product revision; speculative metadata changes are forbidden.
7. Product progress claims require exact repository/CI/runtime evidence. Manager-state prose, old OTK verdicts, or worker reports are not sufficient proof.
8. Candidate knowledge written by a fenced or otherwise invalid execution must be independently revalidated before it becomes durable technical truth.
9. Existing product verification workflows are test infrastructure, not agent orchestration.
10. Until the migration acceptance gate is complete, product-code mutation for the APFS error-79 investigation remains paused.
